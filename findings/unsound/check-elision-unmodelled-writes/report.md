# Unsound: overflow and bounds checks removed for a variable the dataflow lost track of

- class: unsound (a run-time check that must fire is removed; the program wraps or reads past an array with exit status 0, identically at every -O level, so the differential oracle cannot see it)
- found: by hand while auditing check elision for the owner's report that overflow checks keep failing in complex code, then by `oracles/overflow.py`, written for it (seeds 94, 121 against turflang 2.0-era builds)
- repro: `min.tr` prints `-9223372036854775808`; the same with `id(x++)` as a call argument, a copy `y = x` or a sub-expression `(x * 1)` of an `x` changed through `&x`, and `a[i]` after `defer i = 1000000` (a segmentation fault). The compile-time bounds check (E001) shared the dataflow and rejected valid programs the same way (`i--` three times, then `a[i]`)
- cause: `ValueRange.cpp`'s constant propagation modelled only whole-statement writes (`mut x =`, `x =`, `x op=`, `x++`) and trusted every variable unless it recognised the one construct that changed it (`&x`, then `&x` inside `try`, then inside `recover`). Every construct not listed reopened it
- fixed: turflang, default-deny: a variable is tracked only if it is declared in the function and every occurrence of it is a read or one of the four modelled writes as a whole statement; anything else (any node kind, including one added later) leaves it untracked. One solver and transfer serve both the diagnostic and the elision. Tests: `tests/43_check_elision/fail_overflow_*_not_elided.tr`, `fail_bounds_write_in_defer_not_elided.tr`, `constant_index_after_unmodelled_writes_accepted.tr`
